Evaluating the predictions

The datasets, scoring protocol, and results of the local comparison

The comparison uses fifteen DA-2K photographs with thirty-five annotated near and far pairs. Each model processes the original images, two dimming conditions, and a blurred condition. The same coordinates are scored each time. V2 and AC both get thirty-four clean pairs right. Under strong dimming, AC keeps thirty-four and V2 keeps thirty-two. V2 and AC each get 34 of the 35 clean annotated pairs right. That is a useful result, but it only tests the marked points. The indoor sensor examples answer a different question about the shape of a full prediction.

What the datasets provide

NYU Depth V2 contains indoor RGB images and Kinect depth [10]. It provides both projected raw measurements and filled maps. The filled maps help visualize a scene, while the raw data identifies where the sensor supplied usable support.

KITTI’s depth-prediction benchmark uses driving imagery and LiDAR-derived references [11]. Hypersim supplies rendered indoor scenes and geometry [12]. These illustrate how the scene distribution and measurement process change across datasets; the local experiments use NYU and DA-2K.

DA-2K supplies photographs with manually annotated near/far point pairs [13]. Each pair labels which point is closer. It supports an ordering score, without giving us a dense meter-valued reference for the rest of the photograph.

The local experiment

The selection and transformations were fixed before the comparison run. Each of the three models processed the same inputs:

  • 15 DA-2K photographs: the first three lexicographically sorted annotated images in each of five categories, giving 35 pairs.
  • Four conditions: original input; mild dimming, round(255 × 0.25 × (RGB/255)1.6); strong dimming, round(255 × 0.05 × (RGB/255)3); and Gaussian blur with radius min(height,width)/80.
  • Six NYU scenes: zero-based labeled-file records 0, 289, 578, 867, 1156, and 1448.
  • Inference: float32, one image per inference, and a 518-pixel short-edge target with native patch-divisible rounding. V2 and AC use the native V2 processor; DA3 uses its own native processor.

Changing brightness or blur leaves the annotated coordinates in place. This makes it possible to check the same pairs after an appearance change. The dimming is digital postprocessing; physical low-light capture would also involve effects such as sensor noise and exposure time.

Scoring the annotated pairs

For each pair, the model’s inverse-depth values are read at the original image coordinates. The point with the larger value is predicted to be closer. A tie counts as incorrect. The final count includes all 35 pairs in each condition, including failures.

Aligning relative predictions with NYU depth

The relative outputs need a scale and shift before they can be compared with NYU’s meter-valued reference. For each image, the code fits a q + b ≈ 1/Z*, where q is the prediction and Z* is reference depth. It then inverts the fitted values.

Here is a small numerical example. If predicted q values are [1, 2, 3] and target inverse depths are [0.5, 0.75, 1], choosing a = 0.25 and b = 0.25 aligns them exactly. That fit used the target values to find the scale. The same dependence applies to our NYU scores.

How to interpret the aligned error

The fit and score use the same valid reference pixels. This is oracle alignment: it measures shape agreement after access to the reference. It does not show that the raw model can recover those meter distances on a new image.

The mask keeps finite raw sensor and filled reference depths between 0.1 and 10 meters, intersected with rows 45:471 and columns 41:601. These are Python’s end-exclusive slices. The code rejects a non-positive fitted scale and clips aligned inverse values to [0.1,10] before inversion. It records the clipped fraction within the scoring mask.

# Fit relative inverse depth q to inverse reference depth.
mask = valid_sensor_mask & crop & (gt > 0.1) & (gt < 10)
x = q[mask].astype("float64")
target = 1.0 / gt[mask]
A = np.column_stack([x, np.ones_like(x)])
a, b = np.linalg.lstsq(A, target, rcond=None)[0]
if a <= 0:
    raise ValueError("Reversed ordering")
aligned = 1.0 / np.clip(a * q + b, 0.1, 10.0)
abs_rel = np.mean(np.abs(aligned[mask] - gt[mask]) / gt[mask])

The reported metrics

AbsRel averages absolute error divided by reference depth. RMSE is the square root of mean squared meter error, which gives more weight to large errors. Lower is better for both. δ₁ reports the fraction of pixels where max(prediction/reference, reference/prediction) is below 1.25; higher is better. Limits of this comparison

The 15 photographs form a small fixed subset, and the six NYU records are illustrative examples rather than a verified official test split. Multiple pairs from one image and transformed copies of that image are correlated. Neither 180 predictions nor millions of scored pixels should be counted as independent test scenes. Training-data overlap has not been audited.

The V2-to-DA3 comparison changes architecture and training together. It cannot isolate the contribution of a particular component. These results describe the selected checkpoints on this protocol; a larger, independently sampled test would be needed to compare general performance.

The viewer also reports rank stability: Spearman correlation between original and changed predictions at up to 30,000 sampled pixels. It measures whether the predicted ordering stays similar. A consistently wrong ordering can have high stability.
