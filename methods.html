A depth network has to recognize useful image patterns and turn them into a value at each pixel. Foundation models provide a starting representation; depth training teaches the system how to use it for geometry.

From image features to a depth map

DPT combines transformer features with a decoder for dense prediction [2]. Its role is easier to follow by separating the image representation from the output map: the encoder extracts features, and the decoder reorganizes and combines them at different spatial resolutions.

In the V2 implementation used here, the input is resized and normalized before entering the encoder. The decoder predicts relative inverse depth, and the result is interpolated back to the original image grid. That last step lets us look up a prediction at the coordinates of an annotated point.

Inside the encoder and decoder

A vision transformer represents image patches as feature vectors. In a self-attention layer, learned projections produce queries Q, keys K, and values V. The calculation softmax(QKᵀ/√d)V mixes the value vectors using weights derived from query/key similarity; d is the key-vector dimension.

This gives a patch access to information from other parts of the image. Features around a chair can incorporate room context beyond the chair itself. The network then has to learn which relationships help the depth task. Attention weights describe feature mixing, so they should not be read directly as distances or as proof of the cause of a particular prediction.

The decoder brings features back into a spatial arrangement and combines broad context with finer detail. Coarser features can support room layout, while finer ones can support edges. A prediction head produces the output field. Interpolating that field to the original resolution aligns it with the photograph, but a larger output array does not restore detail already lost inside the model.

Depth Anything V2: learning from a teacher

Depth Anything V2 uses a DINOv2-based teacher trained with synthetic depth, then uses that teacher to generate depth pseudo-labels for real images. Student models learn from those pseudo-labels [3]. This connects precise synthetic supervision with the varied appearance of real photographs.

A pseudo-label is a model-generated target. It expands the available training data, while carrying the teacher’s errors into student training. The Small checkpoint in this project outputs relative inverse depth; V2’s separately trained metric checkpoints address a different output requirement.

Marigold: adapting an image-generation model

Marigold starts from Stable Diffusion. It keeps the latent representation and fine-tunes the denoising network to generate depth conditioned on an image [4]. Its original output is affine-invariant depth. Compared with a direct prediction network, this gives another route for transferring knowledge from broad pretraining into a depth task.

These two approaches make “foundation model” more concrete. One transfers visual features into a depth predictor; the other adapts a generative model to produce a depth representation. In either case, the pretrained components, output convention, and training objective need to be specified.

Models that target physical distance

Metric3Dv2 uses canonical camera-space transformations to handle differing camera intrinsics and estimates depth together with surface normals [5]. Depth Pro uses a multiscale transformer system for sharp metric depth and includes focal-length estimation [6].

These methods matter when the application needs meters. Their use also raises practical camera questions: is the focal length known or estimated? Has cropping changed the intrinsics? Does the depth convention match the reference? A model intended for metric prediction still needs testing on the camera and scenes used in the application.

DepthAnything-AC: adapting to appearance changes

AC fine-tunes a pretrained depth model using unlabeled images, perturbation consistency, and a patch-level spatial-distance constraint [7]. It encourages the student to retain geometry under appearance changes, using a frozen model as an anchor. The spatial constraint adds information about relations between patches.

This is the closest adaptation comparison in the local study: V2 Small and the authors’ adapted AC Small checkpoint share the native V2 architecture and preprocessing. The experiment tests their saved weights. I did not train or fine-tune a new model.

Newer directions: DA3 and DepthART

Depth Anything 3 supports any-view geometry with a transformer and a joint depth/ray representation [8]. I ran the DA3-Small any-view checkpoint with one image. The project also has separate large monocular and metric variants, so this test covers one specific member of the family.

DepthART, published as a 2026 research paper, studies distillation into a tiny model and camera-specific adaptation [9]. It extends the discussion to devices where model size and camera differences matter. It is included in the literature review; device experiments with DepthART would be a separate next step.

What was implemented

The local comparison runs V2 Small, AC Small, and DA3 Small. Marigold, Metric3Dv2, Depth Pro, and DepthART help explain alternative approaches in the literature.

Why the training objective matters

Consider a relative predictor that gets the layout right but uses a different scale from its target. Direct squared error can penalize the scale difference heavily. A simplified affine-invariant objective fits scale and shift before comparing compatible quantities: minₐ,ᵦ mean((a q + b − q*)²). Requiring a positive scale preserves the near/far direction.

An edge term can compare spatial gradients, adding pressure to preserve boundaries. A consistency objective compares an image with an appearance-transformed version after matching coordinates and scale. These are useful abstractions for understanding the training choices. Exact losses also involve model-specific masking, normalization, weights, and constraints described in the primary papers.

Consistency has a weakness worth keeping in mind: a model can repeat the same wrong prediction on both versions of an image. Severe transformations can also remove the visual clues needed to predict a surface. Stability needs to be evaluated alongside a reference-based measure.

Designing a fine-tuning study

A follow-up adaptation experiment would need separate training, validation, and test images, an untouched pretrained baseline, and a clear choice about which layers to update. Validation data would determine when to stop training. A clean-domain test set would check whether improvement on the target domain came with a loss elsewhere.

This also distinguishes a checkpoint comparison from a training ablation. Comparing V2 with AC shows how two sets of weights behave. To isolate the effect of a consistency loss or a spatial constraint, the training setup would need to hold other choices fixed and vary that component.
